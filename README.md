# Music Genre Filter

[![CI](https://github.com/tulle-32/Pet_Project_3_Music_Genre_Filter/actions/workflows/ci.yml/badge.svg)](https://github.com/tulle-32/Pet_Project_3_Music_Genre_Filter/actions/workflows/ci.yml)

Сервис, который берёт список музыки со страницы ВКонтакте, сам определяет жанр
каждого трека и позволяет отфильтровать чужую библиотеку по жанру.

**Задача, ради которой всё затевалось.** У друга 1918 треков. Ты любишь рок.
Слушать всё подряд, чтобы найти в этой куче рок, — не вариант. Вставил ссылку
на страницу с музыкой → получил список только из рока → выгрузил плейлистом.
Эта задача решена целиком — см. «Статус» ниже.

---

## Статус

**Проект завершён на v0.8.0.** Вся цепочка работает от начала до конца:
расширение браузера собирает список музыки со страницы ВК → `music import
file` заливает его в базу → `music enrich run` определяет жанры через
Last.fm → `music filter rock --library "..."` печатает отфильтрованный
список в терминал, отсортированный по уверенности.

- **v0.1.0–v0.5.0** — документация, фундамент, база с миграциями, импорт
  из файла, первый CI (GitHub Actions: форматирование, статический анализ,
  сборка, тесты).
- **v0.6.0 — источник ВК.** Расширение браузера (`extension/`) ставится
  в обычный, уже залогиненный браузер, слушает сетевые ответы открытой
  вкладки и выгружает треки файлом JSON — тем же форматом, что понимает
  `music import file`. Почему так, а не иначе — Р-013–Р-016 в
  [docs/DECISIONS.md](docs/DECISIONS.md).
- **v0.7.0 — жанры из Last.fm.** Клиент API (`internal/enrich/lastfm`),
  кэш ответов в базе на 30 дней, справочник тег → жанр
  (`data/genre_map.json`), расчёт уверенности (`internal/taxonomy`),
  пайплайн обогащения (`internal/enrich/pipeline.go`), команды
  `music enrich run`/`enrich list`.
- **v0.8.0 — фильтр по жанру.** `music filter <жанр> --library "Имя"` —
  сам смысл всего проекта: печатает треки нужного жанра (с поджанрами)
  в терминал.

Почему на этом остановились, а не пошли дальше по изначальному плану
(веб-интерфейс, HTTP API, второй провайдер жанров, пользователи) —
Р-020 в [docs/DECISIONS.md](docs/DECISIONS.md). Всё несделанное — не
забыто, а осознанно перенесено в раздел «Идеи на будущее» в
[docs/ROADMAP.md](docs/ROADMAP.md).

**Пошаговая инструкция по использованию — от установки расширения до
отфильтрованного списка — в [docs/USAGE.md](docs/USAGE.md).**

## Быстрый старт

Ниже — сокращённая версия на примере встроенных тестовых треков.
Пошаговая инструкция с настоящей выгрузкой из ВК и всеми возможными
ошибками — [docs/USAGE.md](docs/USAGE.md).

Нужны Go 1.24+ и Docker с плагином compose.

```bash
# 1. Настройки: скопировать образец и поправить пароль
cp .env.example .env

# 2. Скачать зависимости (создаст go.sum с контрольными суммами)
go mod tidy

# 3. Поднять PostgreSQL в контейнере
docker compose up -d

# 4. Убедиться, что база здорова — в колонке STATUS должно быть healthy
docker compose ps
```

Любая команда `music ...` ходит в базу напрямую, поэтому **контейнер должен
быть поднят каждый раз, когда садишься работать заново** — не только один
раз при установке. Если Docker Desktop не запущен или контейнер остановлен,
команды падают с чем-то вроде `dial tcp ... connection refused` — это не
баг, это просто "сначала подними базу": `docker compose up -d`, дождись
`healthy` в `docker compose ps`, и повтори команду.

```bash

# 5. Накатить схему базы и залить справочник жанров
go run ./cmd/music db up
go run ./cmd/music seed genres

# 6. Загрузить пример треков
go run ./cmd/music import file data/samples/sample_tracks.json --library "Рус-Лан"

# 7. Определить жанры через Last.fm (нужен LASTFM_API_KEY в .env;
#    если ты в России — включи VPN, см. Р-017 в docs/DECISIONS.md)
go run ./cmd/music enrich run --limit 20

# 8. Получить отфильтрованный список — вот он, весь смысл проекта
go run ./cmd/music filter rock --library "Рус-Лан"
```

Посмотреть, что получилось:

```bash
go run ./cmd/music db status        # какие миграции применены
go run ./cmd/music genres tree rock # ветка рока в дереве жанров
go run ./cmd/music stats            # сводка по библиотекам
go run ./cmd/music import list      # история импортов
go run ./cmd/music library list     # точные названия библиотек
go run ./cmd/music enrich list      # история прогонов обогащения жанрами
```

Опечатался в названии библиотеки при импорте (бывает, набирали руками)?
Поправить, ничего не переимпортируя:

```bash
go run ./cmd/music library list                       # посмотреть, как записано на самом деле
go run ./cmd/music library rename "ус-ан" "Рус-Лан"    # переименовать точно
```

Что должно получиться на примере: 29 строк выгрузки превращаются в 21 трек.
Разница — дубли, которые схлопнула нормализация: `Nirvana`, `NIRVANA`
и `  nirvana  ` это один исполнитель, а `Smells Like Teen Spirit`,
`Smells Like Teen Spirit (Official Video)` и `smells like teen spirit [HD]` —
один трек с тремя идентификаторами из источника.

### Отдельно: HTTP-сервер (необязательно)

`cmd/server` — самостоятельный HTTP-сервис, но к фильтрации по жанру
отношения не имеет: он умеет только `/health` и `/ready` (задел на
будущий HTTP API, который решили не делать — Р-020 в
`docs/DECISIONS.md`). Для повседневной работы с проектом (импорт,
обогащение, фильтр) он не нужен, запускать его не обязательно.

```bash
go run ./cmd/server
```

Проверка, что всё живо:

```bash
curl http://localhost:8080/health   # процесс жив
curl http://localhost:8080/ready    # база отвечает
```

Ответ `/ready` при поднятой базе:

```json
{
  "status": "ready",
  "database": "доступна"
}
```

Если база не поднята, тот же эндпоинт вернёт **503** и напишет, что именно
не так. Это не ошибка приложения, а его штатное поведение: сервис умеет
работать, пока база догружается, и честно сообщает, что пока не готов.

Остановить сервис — `Ctrl+C`. В журнале появится «получен сигнал остановки»
и «остановлены штатно»: сервер не умирает мгновенно, а даёт текущим запросам
доработать.

## Как это устроено

Приложение состоит из четырёх слоёв, и каждый следующий ничего не знает
о предыдущем — это позволяет менять один слой, не трогая остальные.

**1. Источник треков.** Отдаёт сырой список: исполнитель, название,
длительность. Источники — обычный файл JSON/CSV и тот же формат, который
выгружает расширение браузера для ВК (`extension/`, см. выше). Оба заходят
через один интерфейс `TrackSource`, поэтому ядро приложения не знает и не
должно знать, файл это с диска или выгрузка из ВК.

**2. Нормализация.** Строки из ВК набивали живые люди годами: `Nirvana`,
`NIRVANA`, `Nirvana (Live)`, `Smells Like Teen Spirit (Official Video)`.
Прежде чем что-то с ними делать, их нужно привести к сравнимому виду и
схлопнуть дубликаты.

**3. Обогащение жанрами.** Самая интересная часть. В данных ВК жанра нет
вообще — только исполнитель и название. Жанр добывается из внешнего
справочника — Last.fm (второй и третий провайдер обсуждались, но признаны
лишними для решения исходной задачи, Р-018 в `docs/DECISIONS.md`), каждый
ответ кэшируется в базе на 30 дней, а результат получает число уверенности
от 0 до 1, чтобы было видно, насколько можно доверять конкретному ответу
(`music enrich run`).

**4. Фильтр.** Жанры организованы деревом: запрос «рок» автоматически
захватывает панк-рок, хард-рок и гранж (`music filter rock --library
"..."`). Таблица ручных правок (`overrides`) заложена в схеме и уже
учитывается в SQL-запросе фильтра, но команды, которая бы её заполняла,
пока нет — если алгоритм ошибётся, поправить можно только напрямую в
базе.

Подробно, со схемами и SQL: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

## Стек

| Что | Чем | Зачем именно так |
|---|---|---|
| Язык | Go | Язык инфраструктурного мира. Никакой скрытой магии: путь запроса виден глазами, каждая ошибка обрабатывается явно |
| HTTP | стандартный `net/http` | Веб-фреймворк для этой задачи не нужен, стандартной библиотеки хватает |
| База | PostgreSQL | Рекурсивные запросы для дерева жанров, массивы, JSONB |
| Драйвер | `pgx` | Пул соединений, самый живой драйвер PostgreSQL для Go |
| Запросы | обычный SQL через `pgx` | ORM нет: видно ровно те запросы, что уходят в базу. Генератор `sqlc` подключим в v0.4.0, когда запросов станет много |
| Миграции | `goose` | Каждое изменение схемы — отдельный файл с накатом и откатом |
| Журнал | `log/slog` | Структурированный журнал из стандартной библиотеки |
| Тесты | стандартный `testing` | Плюс временный PostgreSQL в контейнере |
| CI | GitHub Actions | Линтер и тесты на каждый push и pull request. Сборки Docker-образа нет — не потребовалось (Р-020) |

Зависимостей в проекте намеренно мало: HTTP-сервер, шаблоны, JSON, тесты
и журналирование есть в стандартной библиотеке Go.

## Структура

```
cmd/server/        точка входа HTTP-сервиса (минимальный: /health, /ready)
cmd/music/         утилита командной строки: миграции, справочник, отчёты
extension/         расширение браузера — выгружает список из ВК файлом JSON
internal/config/   все настройки из окружения в одном месте
internal/storage/  подключение к базе, миграции, запросы
internal/web/      маршруты и обработчики HTTP
internal/sources/  сменные источники треков: интерфейс и реализации
internal/normalize/ приведение грязных строк к сравнимому виду
internal/enrich/   добыча жанра из Last.fm (единственный провайдер, Р-018)
internal/taxonomy/ сведение тегов провайдера к справочнику жанров
migrations/        миграции схемы, встроены в бинарник
data/              справочник жанров (genre_map.json), растёт руками
docs/              архитектура, решения, дорожная карта
```

Подробная и постоянно обновляемая версия этого дерева, с описанием каждого
будущего подпакета — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Папка `internal/` — правило самого Go: пакеты внутри неё невозможно
импортировать из чужого проекта, компилятор это запрещает.

## Ограничения, о которых честно

Официальный API ВКонтакте не отдаёт аудиозаписи обычным приложениям: метод
`audio.get` требует прав доступа, которые не выдаются с 2016–2017 годов.
Авторизация через VK ID даёт только личность пользователя — имя, аватар,
почту — но не музыку.

Поэтому список треков читается со страницы, которую пользователь и так видит
в браузере — но не автоматизацией снаружи (это пробовали, не прижилось, см.
Р-013–Р-015 в [docs/DECISIONS.md](docs/DECISIONS.md)), а расширением браузера
(`extension/`), которое работает изнутри той же вкладки, что человек и так
открыл сам, в своём обычном, уже залогиненном браузере. Программе на Go
вообще не нужно ничего знать про cookie, токены или порты отладки — она
только принимает готовый файл JSON, который расширение выгружает по кнопке.
Мы читаем **только метаданные** — исполнителя, название и длительность.
Аудиофайлы не скачиваются и не хранятся.

Именно из-за хрупкости внутреннего формата ответов ВК источник треков вынесен
в сменный интерфейс (`TrackSource`): если завтра ВК поменяет разметку своего
API, чинить придётся один файл разбора внутри расширения, а не весь проект.
Разбор механики целиком: [docs/VK_ACCESS.md](docs/VK_ACCESS.md) и
[extension/README.md](extension/README.md).
